# Daily Original Games

首要目标：每天完成一款完整可玩的原创 HTML 游戏 demo，实际试玩检查后推送到独立公开 GitHub 仓库，并部署、验证其 GitHub Pages。调研和方案仅服务于原创设计，不可玩的脚手架不算完成。

每天北京时间 **03:00（Asia/Shanghai）** 启动，当天完成交付。每日游戏见下方索引。

## 每天一个独立仓库

- 仓库命名：`xiangjianan/daily-original-game-YYYY-MM-DD`，日期采用北京时间。
- 每个仓库各自配置 GitHub Pages，从 `main` 分支根目录发布。
- 试玩地址：`https://xiangjianan.github.io/daily-original-game-YYYY-MM-DD/`。
- 本仓库仅承担总索引与协调；每次更新本 README 和根 `index.html` 的日期、游戏名、核心玩法、独立仓库和 Pages 链接。
- 保留已有成果。历史 `games/` 目录不再用于保存新游戏。

每个游戏仓库包含：

- `index.html`：完整可玩的入口，优先原生 HTML/CSS/JavaScript。
- `assets/`：需要的本地素材。
- `README.md`：操作说明、试玩与仓库链接，以及简短中文设计总结。
- `research.md`：具体参考游戏、来源链接、访问日期、数据时间范围、热度证据与复玩机制分析。
- `design.md`：原创规则、心理钩子、与参考游戏和历史作品的差异、素材来源。
- `tests.md`：实际本地与线上浏览器测试、结果和已知限制。

## 开发前调研与原创设计

必须先联网搜索市场上好玩、热门的休闲游戏，记录可核查来源与热度证据，区分事实与推断，不编造数据。提取设计思路和吸引玩家投入、反复游玩的机制，进行原创组合，不完全照搬。不得抄袭代码、美术、角色、品牌、关卡或独特规则组合；阅读历史作品，避免重复核心玩法或仅换皮。

按当日玩法合理落实以下方向，并说明实现方式或不适用原因：

- 三秒钟上手；单局几十秒到几分钟。
- 即时反馈和有爽感的音效（交互后启动、可静音）。
- 难度爬坡、随机性和再次挑战的动力。
- 可对外分享游戏链接或成绩。

## 每日完成条件

1. 当天完成完整原创游戏，具备清晰操作、完整循环、计分或目标、结束反馈与重开，兼顾桌面和移动端。
2. 实际浏览器试玩开始、核心操作、计分、结束、重开、音效/静音和分享，检查控制台与布局，修复阻塞问题。
3. 保存调研、原创设计和真实测试记录。不可用静态检查替代试玩。
4. 在当日仓库 README 保存简短中文总结：复玩机制是什么、参考了哪些具体游戏、借鉴哪些心理钩子、原创变化及与参考的区别。
5. 构建和本地测试成功后 commit/push 到独立公开仓库，验证远程提交，等待该仓库 Pages 部署成功并实际检查线上游戏可玩。
6. 更新总索引并 commit/push，验证索引 Pages 部署及当天链接。完成报告附中文总结、游戏 Pages、独立仓库链接和测试结果。
7. 同一天重试时安全续做未完成交付；已完成则不重复生成。创建前检查仓库，同名无关仓库不得覆盖。不删除历史，不强制推送。
8. 只在完成、失败或需要用户处理时通知。认证、联网、测试、构建、推送或部署阻塞必须真实报告并保留工作。
