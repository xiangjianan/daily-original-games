# Daily Original Games

每天调研热门休闲游戏的复玩机制，设计并实现一款原创、可玩的 HTML demo。

## 游戏索引

| 日期（北京时间） | 游戏 | 核心玩法 | 调研与设计 | 测试 |
| --- | --- | --- | --- | --- |

尚未制作第一款游戏。计划每天 03:00（Asia/Shanghai）启动，当天完成并推送。

## 目录

每款游戏存放于 `games/YYYY-MM-DD/`：

- `index.html`：可玩的入口，优先使用原生 HTML/CSS/JavaScript。
- `assets/`：游戏需要的本地素材（如有）。
- `research.md`：联网调研、来源链接、访问日期、热度证据与复玩机制分析。
- `design.md`：原创规则、核心循环、与参考游戏的差异、操作方式与素材来源。
- `tests.md`：实际执行的浏览器测试、结果与已知限制。

## 试玩

克隆或下载仓库后，直接打开对应日期的 `index.html`。如游戏需要 HTTP 环境，在仓库根目录运行 `python3 -m http.server 8000`，访问 `http://localhost:8000/games/YYYY-MM-DD/`。

这是私有仓库。GitHub 文件链接用于访问或下载源码，并非在线试玩页面。

## 每日交付标准

1. 联网核实近期休闲游戏热度，记录可核查证据；区分事实与推断，不编造数据。
2. 提炼短局反馈、策略变化、成长或挑战等复玩机制，形成原创玩法；不复制代码、美术、角色、关卡、品牌或独特规则组合。
3. 阅读历史游戏，避免只换皮或重复已有核心玩法。
4. 当天完成可玩的 HTML demo，包含清晰操作、完整游戏循环、结束反馈及重新开始。
5. 实际在浏览器测试开始、操作、计分、结束和重开，并检查控制台错误与基本移动端适配。
6. 保存调研、设计与测试记录，更新本索引，git commit/push 并核对远程提交。
7. 同一天重试时续做未完成交付；已完成则不重复生成，不覆盖历史成果，不强制推送。
